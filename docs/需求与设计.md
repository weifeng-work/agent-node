# Agent Node —— 局域网多机智能体协作节点 · 需求与设计文档

版本：v0.1（MVP 草案）· 2026-08-19
状态：控制节点核心已实现并打包为单文件 `dist/agent-node.exe`

---

## 一、项目定位

Agent Node 是一个**可独立部署到任一台局域网电脑上的控制节点单文件程序**。
它是从"agent-bus"仓库中剥离出来的**最小化独立项目**，定位是"多机多智能体协作团队"中
每台电脑上常驻的那个节点，承担：总线通信、受控/遥控、局域网互发现、系统状态可见性、
面向 AI 智能体的 MCP 工具接口。

> 设计哲学 MVP：局域网可信、极简、对称、可观察。砍掉服务自愈/NSSM/托盘复杂 UI/强认证。

### 架构关系
```
中心节点(一台, --role hub)：       对称控制节点(若干, --role worker)：
  起 broker(mosquitto)                只连总线
  起 bus_server(HTTP+面板)            受控能力 + 遥控能力
  自身也是控制节点(带全部功能)        局域网发现 + 托盘可见性
  托盘显示全局                         对称（功能子集，等价可互遥控）
```

## 二、用户故事与功能设想（需求来源）

以下需求来自产品讨论，按优先级收敛。

### P0 · 核心闭环（已实现/已验证）
1. **一键部署单 exe**：整个节点打包为单文件 `agent-node.exe`，内含 mosquitto 便携包与
   web 面板，离线可用，双击即启动。
2. **对称控制节点**：每台电脑跑同一个节点进程；所有节点功能等价，可互相遥控执行命令。
3. **自动局域网互发现**：像 LocalSend，节点启动后向局域网广播自己、扫描其他节点，
   托盘实时显示"我发现了哪些节点"。发现协议含 agent_id/名称/总线地址/受控开关。
4. **受控能力（被遥控）**：接收任意节点发来的 `shell_exec` 指令，在本机执行命令并回执。
   托盘菜单可"关闭受控能力"（熔断）。
5. **遥控能力（遥控别人）**：托盘里可对任一发现的节点发起"在此电脑执行命令"，取回执。
6. **系统状态可见性**：托盘图标变色（有节点在线=绿，无=灰），标题显示发现的节点数。
7. **节点可自定义名称**：默认取电脑 hostname/用户名，可在托盘菜单随时修改，便于人类
   记忆"这台电脑/这个节点叫什么"。
8. **端口兜底**：MQTT/HTTP/发现端口各备端口池，防止默认端口被 winNAT/WSL/杀软/已有
   服务占用时自动回退到空闲端口。

### P1 · 通信与 MCP（已实现/已验证）
9. **内嵌 MCP Server**：节点把自身能力封装为标准 MCP 工具，供 Claude Desktop / Cursor
   等 AI 客户端作为 MCP Client 连接。
10. **MCP Server 独立启动**：`--mcp` 走 stdin/stdout 传输，不依赖 GUI，可由智能体的
    JSON 配置自动拉起。
11. **异步任务**：`send_task(wait_seconds=0)` 发完即回，继续对话；回执按 correlation_id
    配对。智能体在会话边界 `check_inbox` 懒取回执（靠提示词/工具描述约束）。
12. **文件传递**：上传到中心 files/ 得 URL → 消息带 URL → 目标凭 URL 下载（Claim-Check）。

### P2 · 中心与协作（hub 已实现；异步/文件/git 部分已就绪）
13. **中心角色**：`--role hub` 额外起 broker + bus_server + web 面板，成为团队中心；
    地址/端口通过发现分发。
14. **消息持久化**：inbox 消息落盘中心 SQLite（MQTT 实时推送 + 库落盘兜底），节点不在/
    重启不丢。
15. **git 分支协作（设想）**：以中心机为 git 中心仓，各智能体独立分支，完成 push 合并。
16. **多智能体分发（设想）**：一个智能体把任务的不同部分分发给多个电脑上的智能体，
    各自完成代码/文件后回传，中心汇总。

### P3 · 探索（未排期）
17. 事件驱动自动唤醒（收到消息自动启会话，替代"会话边界懒取"）。
18. 操作系统级托盘系统通知（消息到达弹出 OS 通知）。
19. 多团队隔离、节点白名单（当前无条件信任局域网）。

## 三、功能需求明细

### 3.1 启动模式
| 模式 | 触发 | 行为 |
|------|------|------|
| 托盘 GUI | 双击 exe / 无参数 | worker 对称节点 + 托盘常驻 + 发现 + 全局可见性 |
| 中心节点 | `--role hub` | + 起 broker + bus_server + web 面板 + 自身 master 控制节点 |
| MCP | `--mcp` | 以 MCP Server 模式启动（stdio），供 AI 客户端连接 |
| headless | `--headless` | 不起托盘，后台/测试 |

### 3.2 命令行参数
| 参数 | 说明 | 默认 |
|------|------|------|
| `--role {worker,hub}` | 节点角色 | worker |
| `--agent-id` | 节点 ID（寻址身份） | `ctl-<hostname>` |
| `--name` | 显示名 | 同 agent-id |
| `--broker-port` | MQTT 端口 | 池内自动选 |
| `--http-port` | HTTP 端口 | 池内自动选 |
| `--discovery-port` | 发现端口 | 池内自动选 |
| `--broker-host` | 外部中心 broker 地址（worker 连中心用） | 127.0.0.1 |
| `--no-control` | 启动时关闭受控能力 | false |
| `--headless` | 不起托盘 | false |
| `--mcp` | MCP Server 模式 | false |

### 3.3 端口池
- MQTT：1883 → 1884 → 1885 → 8883 → 18830
- HTTP：8000 → 8001 → 8002 → 8010 → 8088
- 发现：41830 → 41831 → 41832 → 41840 → 41850

### 3.4 发现协议（beacon 载荷）
`{proto, ver, type:"sym_ctl", agent_id, name, host_name, ips, mqtt_host, mqtt_port,
 http_port, controlled, discovery_port, is_master}`

### 3.5 MCP 工具（8 个）
`list_online_agents, send_task, check_inbox, run_command, read_file, upload_file,
 download_file, reply_task`

### 3.6 托盘菜单
- 显示：`Agent Bus [role] <节点名>`
- 设置节点名…（弹框输入）
- 受控能力（允许被遥控执行命令）✓ 勾选
- 局域网节点数 ≤N
- 每个发现的节点子菜单：在此电脑执行命令 / 打开面板
- hub 额外：打开中心面板
- 退出

## 四、数据目录

运行数据写在与 exe 同目录的 `data/` 下：
- `data/runtime/mosquitto.conf` broker 配置
- `data/runtime/mosquitto/` 便携 mosquitto（首启从内置 zip 解压）
- `data/bus.db` 消息/节点数据库
- `data/files/` 上传文件
- `data/broker.log`、`data/server.log` 日志

## 五、非功能需求

- **可移植**：单文件 exe，离线可用（内含 mosquitto），首启自解压。
- **极简**：无 NSSM/自愈/托盘复杂 UI；进程由用户/上层管理。
- **局域网可信**：不做 HMAC/白名单强认证，假设全可信。
- **可观察**：托盘图标状态 + 标题节点数 + 命令行日志。
- **防端口冲突**：端口池自动回退。

## 六、构建

```bash
pip install -r requirements.txt pyinstaller pystray pillow mcp "mcp<2"
python scripts/build_mosquitto_zip.py   # 生成 build/mosquitto.zip
python -m PyInstaller build/control_app.spec --noconfirm
# 产物 dist/agent-node.exe
```
