# agent-node 协议与架构（深文档）

> **门控文档**（设计 2.17.7）：默认不向 AI 暴露、不随 SKILL 分发。
> 仅**重大意外 + 人类明确允许**时提供给 AI 做深度排查。
> 常规使用请读 `skill/SKILL.md`；本文是线级协议与架构的完整规范。

版本：2026-08-20（对应施工 `docs/重构设计方案.md` 附录 A）

## 一、总体架构

```
每节点（自用局域网，明文，全放开）：
┌──────────────────────────────────────────────┐
│ 节点核心 NodeCore（node/core.py）             │
│  · UDP beacon 发现（多端口冗余，三路送达）     │
│  · TCP mesh 长连接（附录 A 线级协议）         │
│  · 任务三模式（sync/async/trigger）           │
│  · 三开关门控（allow_shell/file/ai_task）     │
├──────────────────────────────────────────────┤
│ 执行器注册表（executors/registry.py）         │
│  · 统一插件接口 2.2.15 + 结果文件契约 2.2.11  │
│  · 适配器: workbuddy(GUI/UIA) · codebuddy×2   │
├──────────────────────────────────────────────┤
│ 文件控制面 · 聊天 · shell · Syncthing 托管    │
├──────────────────────────────────────────────┤
│ Web 面板 FastAPI(127.0.0.1:5177) = 本地 API   │
│ MCP Server（stdio 薄桥→面板 REST）· cli.py    │
└──────────────────────────────────────────────┘
```

关键设计决策：
- **无中心**：全连接 mesh，每对互通节点一条 TCP 长连接
- **fire-and-forget + 超时**：不做应用层 ACK（TCP 保证传输）；msg_id 去重防重发
- **结果文件契约**：一切执行器结果经 `result.md` 回收（存在 + 大小稳定 N 轮）
- **A2A 数据模型**：任务生命周期复用 A2A v1.0 语义（不声称合规 custom binding）

## 二、发现层（UDP beacon，2.16.2）

载荷：`{v, node_id, name, team_id, ips, ports:{peer_tcp, discovery[]},
switches, capabilities[], sync_device_id, seq}`

- **四路送达**（实测部分 Windows 不收 255.255.255.255）：
  全网广播 + 子网定向广播（192.168.x.255）+ 已知对端单播 + **组播（3.x，默认组
  `239.255.42.47`）**——组播与广播正交，广播被过滤但组播放行时互为兜底
- 去重：`node_id@gen + seq`（同 beacon 从多端口到达只处理一次；gen=启动时间戳，重启后 seq 冲突不误丢）
- 默认发现端口集：`41830/41550/60420/31820/26880`（避开 LocalSend 53317）
- 团队隔离：beacon 所有人可见；**TCP 建连时校验 team**（不一致回 error 并断开）
- **固定通告 TCP 端口（3.x）**：主 mesh 对等端口动态分配，另监听固定通告端口
  （默认 `49700`，占则顺延 49700–49704）；子网扫描先拨通告端口（每 IP 1 端口）
  读 whoami 拿真实对等端口，免盲扫 20 口对等段

在线判定（2.1.6）：beacon 超时 6s → TCP 探测（1s 间隔 × 3 次失败 → 离线）。

## 三、TCP mesh（附录 A 线级协议）

### 帧格式（A.2）

```
[1B frame_type][4B 大端长度 N][N B 载荷]
0x01 JSON 控制帧（UTF-8 信封）
0x02 文件块帧（16B file_transfer_id + 4B 大端 seq + 原始字节）
单帧上限 8 MiB；文件块默认 1 MiB
```

### 统一信封（A.3）

```json
{"v":1, "msg_id":"<uuid>", "type":"...",
 "sender_node_id":"...", "target_node_id":"...",
 "correlation_id":"<请求msg_id或task_id>", "payload":{}}
```

type 全集：`text_request | shell_exec | shell_result | file_push | file_pull |
file_list | file_list_result | file_ack | file_result | plugin_sync |
plugin_sync_result | executor_status | executor_status_result | a2a_request |
a2a_response | ping | pong | error`

### 连接生命周期（A.1/A.7）

1. 建连后双方各发首帧 `ping`（payload: hello/team_id/name/peer_tcp）
2. team 不一致 → `error(disabled, team mismatch)` → 关连接
3. 去双连接：同时建连保留"较小 node_id 发起"者；被淘汰连接**延迟排空**（在途
   文件传输不中断），关闭不算断线（不触发重连）
4. 保活：5s ping / pong（correlation_id 回关联回 pid）；3 次未回 → 断线重连
   （3s 间隔 × 10 轮）
5. 断线重连：已知地址自动重连；msg_id 去重（sender+msg_id LRU 2048）防重发重复

### 文件传输（A.4，分帧多路复用）

push：`file_push{targetPath,size,sha256,ftid}` → `file_ack{accepted}` →
块帧流（同连接与控制帧交错）→ 校验大小+SHA-256 → `file_result`。
失败清半写文件（要么完整要么不落盘）。

附件特例（2.13.1）：`purpose=task_attachment` 受 `allow_ai_task`（非 allow_file）
管辖，落 `data/executor_work/<agent_id>/<task_id>/`。

### 开关管辖（2.9.4）

| 报文 | 开关 |
|---|---|
| shell_exec | allow_shell |
| file_push/pull/list（普通文件） | allow_file |
| plugin_sync（插件分发） | allow_file |
| file_push(task_attachment) + a2a_request + executor_status | allow_ai_task |
| text_request（聊天）/ ping | 不受开关 |

## 四、A2A 任务层（a2a_request 载荷 = JSON-RPC 2.0）

方法集：`message/send`（提交）、`tasks/get`（查询）。
Task 状态机：`submitted → working → completed/failed`（cancel/input-required 不用）。

三模式（2.7，节点级语义，执行器不感知）：
- **sync**：调用方阻塞；发起方轮询 tasks/get 或等 a2a_response 推送
- **async**：不阻塞；完成时目标节点主动推 `a2a_response`（correlation_id=task_id）
  → 调用方节点按 caller_id 入邮箱；推送失败入重试队列（20s 周期至 10 分钟）
- **trigger**：submit 返回 ok 即"触发成功"确认，无结果回执

幂等（2.13.5）：传输层 msg_id 去重 + 应用层调用方复用 task_id（目标已存在则
返回现状不重复执行）。

## 五、执行器体系

### 统一插件接口（2.2.15 签名，executors/base.py）

```python
class ExecutorPlugin(ABC):
    plugin_id / display_name / executor_type / concurrency
    on_load(ctx) / on_unload() / check_capability() -> CapabilityResult
    submit(task: TaskInput) -> SubmitResult
    is_done(task_id) -> bool
    get_result(task_id) -> ResultPayload
    status() -> ExecutorStatus   # 插件只报 idle/busy；suspended 由核心叠加
```

### 结果文件契约（2.2.11）

提示词要求智能体把结论写入 `data/executor_work/<agent_id>/<task_id>/result.md`
（原子写：.tmp → rename）。完成判定：文件存在 + 大小连续 2 轮稳定 + 超时兜底。

### 并发语义（2.13.2）

- 非交互 CLI（codebuddy-cli）：并发 3，满则 **busy 拒绝不排队**
- 交互式 TUI（codebuddy-tui）：并发 1，**串行排队**（常驻 psmux 会话复用）
- GUI（workbuddy）：并发 1，排队

### 适配器实现要点（实战坑汇总）

**psmux 可见弹窗**（2.2.6）：
- attach 命令走**批处理文件**（`cmd /c batch.cmd` + CREATE_NEW_CONSOLE）——
  Python list2cmdline 与 cmd /S 嵌套引号转义冲突会闪退
- pane 注入超长行（~600 字符）会截断——长命令写 run.ps1，pane 只敲短命令
- psmux 子进程统一注入 `PSMUX_NO_WARM=1`
- kill-session 不杀子进程树 → taskkill /T 兜底

**codebuddy-cli**（非交互 fresh）：
- prompt 经 stdin（argv 多行截断坑）；PS 管道 `Tee-Object` 实时显示+捕获
- 三重 UTF-8 编码（[Console]::Input/Output + $OutputEncoding）防 GBK 乱码
- 完成后醒目重放回复 + 15s 停留；-y 跳权限确认

**codebuddy-tui**（交互式常驻）：
- 就绪判定用 TUI 特征字符（█/│）——欢迎屏有动态内容，"屏幕静止"判不了
- Enter 提交须**延时 1.5s + 验证**（文本进入对话区且输入框清空），过早 Enter
  被吞；失败重发 3 次

**workbuddy**（GUI/UIA）：
- deeplink 预填 + UIA Edit 定位 + Enter；"覆盖草稿"模态先点掉再找输入框
- comtypes COM 线程亲和：每个工作线程用前 CoInitialize
- 提交成功双条件：对话区含任务短码 且 输入框已清空

## 六、面板 / MCP / CLI（三层同源）

Web 面板（FastAPI, 127.0.0.1:5177，被占顺序 +1，URL 落 data/panel.url）=
**节点完整本地 API**。MCP server（stdio）与 cli.py 都是它的薄桥；
caller_id 经 `X-Caller-Id` 头透传（MCP: 由父进程可执行名自动派生，无需配置；
CLI: register 生成的身份文件 / AGENT_NODE_CALLER_ID）。

REST 端点速查：`/api/overview|nodes|node/restart|chat/*|files/list|files/upload|files/push|
files/pull|files/download|files/inbox|executors*|task/submit|task/result|mailbox|
logs/comm|logs/node|settings/*|shell|plugins*|sync/now|sync/status|sync/add|diag`

## 七、存储（data/comm.db，SQLite WAL）

四表：`comm_log`（全量审计）、`mailbox`（异步回执，取走标已读，caller 隔离）、
`chat_messages`（聊天，双方各自本地）。节点列表不落库：面板**仅显示在线节点**（离线即消失，内存元数据 2.1.9）。

## 九、已知边界

- 255.255.255.255 广播部分 Windows 不收（已用三路送达绕开）
- IKUN 锁屏期间 UIA 驱动必然失败（无桌面会话，客观限制）
- psmux pane 默认 PowerShell；脚本注入走 run.ps1 + ExecutionPolicy Bypass
- Syncthing REST 按 id 端点 PUT（列表端点需数组）；设备地址含显式 tcp://IP:22000
